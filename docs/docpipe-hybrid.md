# Разбор документов без ИИ в основе (docpipe, режим hybrid)

**Принцип:** темы и фрагменты документа определяют классические алгоритмы без нейросетей.
Модель (по умолчанию — локальная, текст не покидает сервер) только **выбирает** из кандидатов,
которые нашли алгоритмы, и только в спорных случаях. Модель недоступна — берётся лучший
кандидат по сходству. Точность ниже, чем у «модель решает всё», зато разбор не зависит от ИИ,
воспроизводим и проверяем.

Режим задаёт `NEIROMASTER_DOCPIPE_MODE`: `hybrid` (по умолчанию) или `llm` (прежний — DeepSeek
сам делит и размечает). Код — `backend/docpipe/lexical.py` (алгоритмы, без сети и библиотек)
и `backend/docpipe/pipeline.py` (`_hybrid_label`).

```
документ ─ docling: разделы по заголовкам, таблицы, страницы
   │
   ▼  раздел -> предложения (с признаком «строка начинается с пункта/заголовка»)
   │
   ├─ TextTiling (Hearst, 1997) ─┐  каждый алгоритм голосует за границы между предложениями;
   ├─ C99 (Choi, 2000) ──────────┼─ граница принимается при ≥ 2 голосах (допуск ±1 предложение);
   └─ разметка текста ───────────┘  длинный фрагмент дорезается, короткий приклеивается
   │
   ▼  фрагмент
   ├─ ключевые слова TF-IDF — темы фрагмента, без всяких описаний плана
   └─ кандидаты-подэтапы: TF-IDF-сходство фрагмента с профилем подэтапа
      (название, бриф, «ВКЛЮЧАТЬ», теги — уточняющий материал) минус сходство с «НЕ ВКЛЮЧАТЬ»
   │
   ▼  выбор
   ├─ явный лидер (сходство ≥ 0,18 и отрыв ≥ 0,05) — принимается без модели
   ├─ спорный — модель выбирает 0–3 id ТОЛЬКО из кандидатов
   └─ модель недоступна — лучший кандидат, если сходство ≥ 0,10
   │
   ▼  PostgreSQL: метка раздела (объединение фрагментов) + фрагменты с полной выгрузкой
```

## Алгоритмы

| Что | Как | Без ИИ |
|---|---|---|
| Слова | Токены, стоп-слова, основа слова — стеммер Snowball (Портер) для русского; аббревиатуры (СИЗ, ОТ, ЧПУ) как есть | да |
| TextTiling | Окна по k предложений слева и справа от каждой границы, косинус мешков слов, сглаживание, «глубина долины»; граница — глубже, чем среднее − σ/2 | да |
| C99 | Матрица сходства предложений -> ранговая (маска 11×11) -> деление сверху вниз, пока растёт плотность сходства внутри фрагментов (порог μ + 1,2σ) | да |
| Разметка текста | Нумерация «5.», «5.1», «Статья/Раздел/Глава», заголовок прописными | да |
| Темы | TF-IDF ключевые слова фрагмента (IDF — по разделам документа и профилям подэтапов) | да |
| Подэтап | Косинус TF-IDF фрагмента и профиля подэтапа, штраф за «НЕ ВКЛЮЧАТЬ» | да |
| Служебный текст | Регулярные выражения: «настоящее положение разработано…», область применения, термины, листы ознакомления | да |
| Должности | Все значимые слова названия должности из штатного расписания есть во фрагменте | да |
| Спорный выбор | Модель выбирает из 2–5 кандидатов | локальная модель / DeepSeek / выключено |

## Полная выгрузка

Всё, что насчитали алгоритмы, хранится у каждого фрагмента (`chunks.meta`): кто голосовал за
границу, вес границы, ключевые слова, все кандидаты со сходством и кто выбрал итог.

- `/doc-breakdown` (раздел /globaltest) — фрагменты документа с этими данными;
- `python scripts/export_segmentation.py [файл ...]` -> `Разбор_фрагментов.xlsx` — для фильтрации
  и подбора порогов.

## Настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `NEIROMASTER_DOCPIPE_MODE` | `hybrid` | `llm` — прежняя разметка DeepSeek целиком |
| `NEIROMASTER_DOCPIPE_REFINE` | `local` | кто выбирает в спорных случаях: `local` — локальная модель (служба `llm`), `deepseek` — обезличенный фрагмент в DeepSeek, `off` — только алгоритмы |
| `NEIROMASTER_DOCPIPE_CLEAR_SIM` | `0.18` | сходство явного лидера |
| `NEIROMASTER_DOCPIPE_CLEAR_MARGIN` | `0.05` | отрыв явного лидера от второго |
| `NEIROMASTER_DOCPIPE_ACCEPT_SIM` | `0.10` | без модели лучший кандидат принимается от этого сходства |

Локальная модель — служба `llm` (Qwen3-4B на CPU). В онлайн-режиме её запускают так же, как для
офлайна: `docker compose --profile offline up -d` (+~2,5 ГБ памяти). Не запущена — разметка идёт
без неё (в логе worker'а: «уточнение моделью недоступно»), повторная попытка через 10 минут.

Пороги подобраны на синтетических текстах. На документах заказчика: загрузить 3–5 документов,
выгрузить `export_segmentation.py`, посмотреть, где кандидат верный, но не принят (снизить
`CLEAR_SIM`/`ACCEPT_SIM`), и где принят неверный (поднять).

После смены режима или порогов документы переразмечаются кнопкой «Переразметить» (или
загрузкой заново): метки старого режима остаются до переразметки.
