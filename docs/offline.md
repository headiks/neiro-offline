# Офлайн-версия: работа без доступа наружу

Документы разбираются DeepSeek, пока у сервера есть интернет. Потом доступ наружу
отключается, и сервер отвечает сотрудникам только тем, что лежит у него локально.

## Как отвечает ассистент без интернета

Главное качество закладывается заранее, пока DeepSeek доступен. Офлайн слабая модель
в основном находит готовый ответ и лишь изредка пишет ответ сама.

1. **ЧС** — регулярные выражения, мгновенно. Вопрос уходит специалисту (как онлайн).
2. **База готовых ответов** (`qacache`), ответ мгновенный. Что в ней лежит:
   - топ-10 вопросов по каждому подэтапу и по 2 вопроса на каждую секцию документов —
     написаны DeepSeek;
   - ответы ассистента, накопленные онлайн;
   - ответы специалистов.

   Поиск идёт сначала по точному совпадению слов, затем по смыслу: локальная модель
   эмбеддингов bge-m3 на CPU, около 0,2 с на вопрос.
3. **Локальная модель** (служба `llm`, Qwen3-4B на CPU) — если готового ответа нет.
   - Справка: ближайшая готовая пара «вопрос–ответ» плюс самые близкие к вопросу
     предложения из документов. Фрагменты ищутся гибридно: по смыслу и полнотекстово
     (Postgres, русская морфология).
   - Ответ сохраняется в базу, так что следующий похожий вопрос получит его мгновенно.
4. **Нет уверенного ответа** (модель ответила `НЕТ_ОТВЕТА`) — вопрос уходит специалисту.
   Сотрудник сразу видит похожие вопросы, на которые ответ уже есть. Когда специалист
   ответит и отметит «Добавить в базу ответов», этот ответ будут получать все, кто спросит
   похожее.

## Железо и время ответа

Замер на сервере с 4 vCPU и 8 ГБ, модель Qwen3-4B-Instruct-2507 Q4_K_M:
- модель читает около 12 токенов/с и пишет около 2,5 токена/с;
- ответ по справке из 1200 символов занимает примерно 60–90 с;
- ответ из базы приходит сразу.

Qwen2.5-3B быстрее (около 45 с), но на замере дважды не нашла ответ, который был
в справке, поэтому по умолчанию её не используем.

| Сервер | Что поставить в `.env` |
|---|---|
| 4 vCPU, 8 ГБ | по умолчанию; `WORKER_REPLICAS=1` (разбор документов офлайн не нужен) |
| 8 vCPU, 16 ГБ | `LLM_THREADS=8`, `NEIROMASTER_OFFLINE_CONTEXT_CHARS=2400`, `NEIROMASTER_OFFLINE_ANSWER_TOKENS=300` |

Память в офлайне: llm около 2,5 ГБ, embed около 0,3 ГБ, web около 0,5 ГБ, Postgres
и Redis. Модели обрабатывают по одному запросу за раз: вопросы, заданные одновременно,
встают в очередь.

## Подготовка — пока интернет есть

```bash
docker compose --profile offline up -d                          # скачает модели llm и embed
docker compose exec web python scripts/offline_prepare.py --fix  # догенерировать недостающее
docker compose exec web python scripts/offline_prepare.py        # повторять, пока всё [OK]
docker compose exec web python scripts/offline_eval.py --n 30    # замер качества
```

`offline_prepare.py` проверяет:
- все документы разобраны;
- сообщения плана сгенерированы под все должности из штатки;
- готовы частые вопросы по подэтапам и секциям;
- у фрагментов документов и у ответов есть векторы;
- модели отвечают.

`offline_eval.py` работает так: DeepSeek составляет новые вопросы с эталонными ответами,
офлайн-цепочка на них отвечает, DeepSeek оценивает ответы. В отчёте — доля ответов
из базы, от модели и ушедших специалисту, средняя оценка, доля неверных и время.
По этим цифрам подбирают `NEIROMASTER_QA_SIM` и бюджет справки.

## Переключение в офлайн

1. Добавить в `.env` строку `NEIROMASTER_LLM_MODE=offline` (и `WORKER_REPLICAS=1` на слабом
   сервере).
2. `docker compose --profile offline up -d`.
3. Отключить доступ наружу.

В офлайне загрузка документов, переразметка и генерация сообщений плана отвечают
понятной ошибкой («только в онлайн-режиме»). Всё остальное работает как обычно.

## Новые документы: временно подключить интернет

1. Подключить интернет, в `.env` поставить `NEIROMASTER_LLM_MODE=online`, затем выполнить
   `docker compose up -d`.
2. Загрузить документы. Разметка, сообщения плана и частые вопросы по затронутым подэтапам
   обновятся сами. Ответы модели по этим подэтапам удалятся как устаревшие, ответы
   специалистов останутся.
3. Выполнить `offline_prepare.py`, дождаться, пока всё будет `[OK]`, затем вернуть
   `NEIROMASTER_LLM_MODE=offline`, выполнить `docker compose --profile offline up -d`
   и отключить интернет.

## Настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `NEIROMASTER_LLM_MODE` | `online` | `offline` — все вызовы модели идут в локальную `llm`, тяжёлые операции запрещены |
| `LLM_MODEL` | `unsloth/Qwen3-4B-Instruct-2507-GGUF:Q4_K_M` | модель с Hugging Face (скачивается один раз в том `models-llm`) |
| `LLM_THREADS` | `4` | потоки модели, обычно равно числу ядер |
| `NEIROMASTER_QA_SIM` | `0.84` | порог похожести для готового ответа |
| `NEIROMASTER_OFFLINE_CONTEXT_CHARS` | `1200` | сколько символов справки получает модель |
| `NEIROMASTER_OFFLINE_ANSWER_TOKENS` | `150` | длина ответа модели |
| `NEIROMASTER_OFFLINE_PAIR_MIN` | `0.6` | с какой похожести готовая пара идёт в справку и в «похожие вопросы» |
