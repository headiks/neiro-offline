# Выкатка в продакшен: чек-лист

## 1. До первого запуска

- [ ] Сервер: `./install.sh` (PostgreSQL и Redis в Docker на localhost, systemd `rag-app` и `rag-worker@N`).
- [ ] `.env.production` (права `600`, в git не попадает):
  - `DEEPSEEK_API_KEY` — ключ модели;
  - ключ шифрования ПДн задавать не нужно — он создаётся сам при первом старте в
    `data/secrets/pii.key` (права `600`), а в БД записывается только его отпечаток.
    **Сразу сохраните копию файла отдельно от бэкапов БД**: без ключа зашифрованные ФИО и
    контакты не прочитать. Если сайт работает на нескольких серверах — задайте всем один ключ
    через `NEIROMASTER_PII_KEY` (содержимое файла). Приложение не стартует, если ключ не
    совпадает с тем, которым уже зашифрованы данные (защита от случайной подмены);
  - `REDIS_URL=redis://localhost:6379/0` — без Redis лимиты и блокировка перебора работают в
    памяти каждого процесса по отдельности;
  - `WEB_CONCURRENCY=6`, `NEIROMASTER_DB_POOL=15` (суммарно соединений меньше `max_connections`);
  - по желанию: `NEIROMASTER_ADMIN_PASSWORD` (начальный пароль владельца, от 8 символов),
    `NEIROMASTER_ALLOW_REGISTRATION=0` (если все доступы выдаёт администратор), S3.
- [ ] HTTPS: сайт слушает только `127.0.0.1:8000`, наружу — через Caddy:
  ```
  ваш-домен.ru {
      reverse_proxy 127.0.0.1:8000
  }
  ```
  Кука сессии по умолчанию `Secure` — без HTTPS вход не сохранится (это намеренно).
  `NEIROMASTER_INSECURE_COOKIE=1` — только для локальной разработки.
- [ ] Firewall: открыты только 22, 80, 443. Порты 5432, 6379, 8000 наружу не открывать.

## 2. Первый вход

1. `sudo journalctl -u rag-app | grep -A3 "главного администратора"` — логин и пароль владельца
   (дубль в `data/owner_initial_credentials.txt`, удаляется после смены пароля).
2. Войти, задать свой пароль.
3. Кнопка **«Как пользоваться»** — интерактивный тур по админке и кабинету сотрудника.

## 3. Проверка после выкатки

```bash
curl -s https://ваш-домен.ru/healthz          # {"ok":true,"db":true,"redis":true}
curl -sI https://ваш-домен.ru/login | grep -i -E "content-security|x-frame|strict-transport"
sudo systemctl status rag-app 'rag-worker@*'
```

Полная проверка в браузере (на тестовом стенде с чистой базой):
`E2E_BASE=https://стенд E2E_OWNER_PASSWORD=… python e2e_test.py`.

## 4. Эксплуатация

| Что | Как |
|---|---|
| Мониторинг | `GET /healthz` каждые 1–5 мин; 5xx или `redis:false` — тревога |
| Расход DeepSeek | `GET /api/llm-usage` (суперадмин) — токены по дням |
| Очереди | страница `/queue-test` (суперадмин): воркеры, длина очереди, ошибки |
| Журнал действий | `/logs`: входы, неудачные входы, удаления, выдача паролей, смена ролей |
| Бэкап | `pg_dump` ежедневно + S3 с оригиналами документов. Файл ключа `data/secrets/pii.key` — в отдельном хранилище секретов, не вместе с дампом |
| Обновление | `git pull && sudo systemctl restart rag-app 'rag-worker@*'`. Схема БД и миграции применяются сами при старте; сайт уже собран в `static/app/` — Node.js на сервере не нужен |
| Тесты перед выкаткой | `python tests/run_tests.py` (нужна тестовая БД `NEIROMASTER_TEST_DSN`); CI — `.github/workflows/tests.yml` |

## 5. Нагрузка

- Web: `WEB_CONCURRENCY` воркеров gunicorn; тяжёлая работа (разбор документов, генерация) —
  в `rag-worker@N`, масштабируется их числом. Обработчики API — обычные `def` (FastAPI
  выполняет их в пуле потоков): медленный запрос к БД, S3 или ИИ не останавливает воркер.
  `async def` — только если внутри есть `await` (проверяет `test_routes.py`).
- Статика: приложение само сжимает ответы (gzip) и отдаёт файлы сборки `static/app/assets/`
  с долгим кэшем (в имени — хеш). `encode` в Caddy не обязателен.
- DeepSeek: `DEEPSEEK_MAX_CONCURRENCY` — общий на кластер потолок одновременных запросов.
- Лимиты: `NEIROMASTER_LOGIN_RATE` (входов в минуту с IP, по умолчанию 120 — вся смена за
  одним NAT), `NEIROMASTER_ASK_RATE` (вопросов в минуту на человека, 20).
- Нагрузочный прогон: `python scripts/loadtest.py` на стенде.

### Сайт не загружается или падает при переходах

- Ошибки интерфейса пишутся в «Журнал действий» (тип «Ошибка интерфейса»): текст, стек,
  страница и сборка. На экране ошибки — «Подробности для администратора».
- `curl -s https://домен/healthz` несколько раз подряд: поле `build` всегда одно и то же и
  совпадает с `static/app/index.html` на сервере. Разные значения — за прокси работают
  разные копии приложения или кэш по дороге отдаёт старую страницу (HTML кэшировать нельзя).
- Сайт собран в один файл: переход между разделами ничего не догружает из сети. Если файл
  сборки не пришёл при открытии, вкладка один раз обновляется сама, потом — сообщение.

## 6. Что изменилось при этой выкатке (миграции выполняются сами)

- Реестр документов (`data/registry.json`) и вопросы сотрудников (`data/pending_questions.json`)
  переносятся в таблицы `doc_registry` и `questions`; файлы переименовываются в `*.migrated`.
- Даты выхода вида `15.05.2026` приводятся к `2026-05-15` — сотрудники из штатки начнут
  получать сообщения плана.
- Сессии переводятся на хэши токенов при первом обращении — перелогиниваться не нужно.
- Сайт — собранное React-приложение (`static/app/`), шрифт и иконки внутри сборки, внешних
  запросов со страниц нет; CSP не разрешает inline-скрипты.
